+# Лабораторна робота №4 — Опрацювання жестів користувача та реалізація інтерактивної взаємодії у React Native
+
+## Опис проєкту
+Мобільний застосунок «Clicker» для опрацювання жестів користувача та інтерактивної взаємодії. Застосунок містить три вкладки:
+1. **Гра** (головний екран) — містить лічильник очок, інтерактивний об'єкт (кнопка у вигляді відбитка пальця розміром 140x140 пікселів), 
панель останньої події та картки підказок з правилами жестів. Об'єкт реагує на такі жести:
+   - `TapGestureHandler` (одиночний клік) — дає +1 очко.
+   - `TapGestureHandler` (подвійний клік) — дає +2 очки.
+   - `LongPressGestureHandler` (утримання протягом 3 секунд) — дає +10 очок і анімацію заповнення.
+   - `PanGestureHandler` (перетягування) — переміщує об'єкт по екрану в межах контейнера (з обмеженням `clamp`) та зараховує перетягування
при зсуві від 30 пікселів.
+   - `FlingGestureHandler` (швидкий свайп вправо або вліво) — генерує випадкову кількість очок від 1 до 10 та анімує нахил об'єкта.
+   - `PinchGestureHandler` (масштабування двома пальцями) — змінює масштаб об'єкта в діапазоні від 0.6 до 2.2 та дає +5 очок при зміні 
масштабу щонайменше на 15%.
+   - Комбо-жест — нарахування +15 бонусних очок, якщо зробити подвійний клік не пізніше ніж за 3 секунди після свайпу.
+2. **Завдання** — перелік із 8 завдань із прогрес-баром та статусом виконання («Виконано» / «В процесі»):
+   - Зробити 10 кліків (ціль: 10).
+   - Зробити подвійний клік 5 разів (ціль: 5).
+   - Утримувати об'єкт 3 секунди (ціль: 1).
+   - Перетягнути об'єкт (ціль: 1).
+   - Зробити свайп вправо та свайп вліво (ціль: 2).
+   - Змінити розмір об'єкта (ціль: 1).
+   - Отримати 100 очок (ціль: 100).
+   - Комбо: свайп + подвійний клік (власне завдання на основі комбінації жестів, ціль: 3).
+3. **Налаштування** — відображення загальних параметрів (назва, версія з `expo-constants`, перемикач підказок), довідник нарахування очок,
статистика прогресу та кнопка повного скидання прогресу з підтвердженням через `Alert.alert`.
+
+Дані керуються через `GameProvider` (`useReducer`) у пам'яті та скидаються при перезапуску або кнопкою скидання.

+## Висновки
+
+У ході лабораторної роботи було успішно освоєно методи розпізнавання та опрацювання користувацьких жестів у React Native за допомогою 
бібліотеки `react-native-gesture-handler` спільно з `react-native-reanimated`. Реалізовано комплексний ігровий додаток «Clicker», який 
підтримує одиночні та подвійні кліки, утримування, перетягування, швидкі свайпи та масштабування, а також комбінацію жестів. Працездатність
перевірена на екранах гри, завдань та налаштувань із синхронізацією стану через React Context.
+
+**1. Які основні типи жестів надає бібліотека react-native-gesture-handler та для яких сценаріїв взаємодії вони призначені?**
+Бібліотека `react-native-gesture-handler` надає набір обробників для різних сценаріїв дотику. `TapGestureHandler` призначений для 
одиночних або множинних коротких натискань (наприклад, кліки по кнопках). `LongPressGestureHandler` використовується для реагування на 
утримання об'єкта протягом певного часу. `PanGestureHandler` застосовується для перетягування елементів у будь-якому напрямку вздовж 
екрана. `FlingGestureHandler` створений для швидких змахів (свайпів) у заданому напрямку. `PinchGestureHandler` використовується для 
масштабування об'єктів за допомогою двох пальців, а `RotationGestureHandler` — для їх обертання.
+
+**2. У чому відмінність між обробкою переміщення об'єкта за допомогою PanGestureHandler та швидкого зсуву через FlingGestureHandler?**
+`PanGestureHandler` призначений для безперервного відстеження переміщення пальця (dragging), коли об'єкт плавно слідує за пальцем 
користувача під час руху на екрані. Натомість `FlingGestureHandler` реагує на швидкий імпульсний рух (свайп), який завершується миттєво, 
після чого зазвичай спрацьовує анімація відскоку або повернення об'єкта у вихідне положення чи перемикання стану. Pan опрацьовує кожен кадр
переміщення у `onUpdate`, тоді як Fling спрацьовує у момент активації швидкого кидка.
+
+**3. Навіщо у корені застосунку необхідно обгортати компоненти в GestureHandlerRootView?**
+Кореневий компонент `GestureHandlerRootView` є обов'язковим обгортковим елементом, оскільки на платформах Android та iOS він ініціалізує 
та надає рідний контекст обробки жестів (Native Gesture Handler Root). Без цього компонента нативні обробники дотиків не зможуть коректно 
перехоплювати події жестів від операційної системи, що призведе до збоїв або повної відсутності реакції на жести в застосунку.
+
+**4. Яким чином можна реалізувати одночасне або послідовне спрацьовування кількох жестів на одному елементі?**
+Для одночасного спрацьовування кількох жестів на одному елементі використовується хук або функція `useSimultaneousGestures` (або 
сумісність через `.simultaneousWithExternalGesture()`), яка дозволяє виконувати, наприклад, паралельне панорамування та масштабування 
(`pan` і `pinch`). Для послідовної або вибіркової взаємодії застосовуються `useExclusiveGestures` (де спрацьовує лише один жест із 
пріоритетом, наприклад, подвійний клік перекриває одиночний) або логічні умови зв'язування у стані та обробниках подій.
