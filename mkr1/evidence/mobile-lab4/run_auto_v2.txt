+# Лабораторна робота №4 — Опрацювання жестів користувача та реалізація інтерактивної взаємодії у React Native
+
+## Опис проєкту
+
+Мобільний застосунок «Clicker» є інтерактивною грою з підтримкою розширеної жестової взаємодії за допомогою бібліотеки 
`react-native-gesture-handler` та анімацій через `react-native-reanimated`. Додаток містить головний ігровий екран з інтерактивним 
об'єктом, сторінку завдань для відстеження прогресу та сторінку налаштувань для керування параметрами і скидання даних.
+
+На головному екрані користувач взаємодіє з центральним елементом за допомогою одиночних та подвійних натискань, тривалого утримання, 
перетягування (pan), швидких свайпів (fling) та масштабування (pinch). Кожна успішна дія оновлює лічильник очок і зараховує прогрес за 
відповідними завданнями. Додаток містить 8 завдань, серед яких є класичні кліки, утримання, перетягування, свайпи вліво/вправо, зміна 
розміру, набір 100 очок та власне комбіноване завдання.
+
+Дані та ігровий прогрес (очки, стан завдань, статистика жестів) зберігаються локально в пам'яті застосунку за допомогою ігрового контексту
`GameProvider` та стейту. На сторінці налаштувань доступні перемикачі вібрації, звуків, темної теми, а також функція повного скидання 
прогресу.
+
+Стек: Expo SDK ~58.0.23, React 19.3.0, React Native 0.88.1, expo-router ~58.0.30, react-native-gesture-handler ~3.3.0, 
react-native-reanimated 4.7.1, react-native-safe-area-context ~5.11.1.

+## Висновки
+
+Реалізовано мобільний застосунок «Clicker» із підтримкою складної жестової взаємодії за допомогою бібліотеки 
`react-native-gesture-handler` та `react-native-reanimated`. Ключові техніки включають композицію жестів, обробку подвійних кліків, 
утримання, перетягування, свайпів та масштабування з оновленням ігрового стану. Працездатність та коректність нарахування очок перевірено 
на ігрових екранах та через систему завдань.
+
+**1. Які основні типи жестів надає бібліотека react-native-gesture-handler та для яких сценаріїв взаємодії вони призначені?**
+
+Бібліотека надає набір обробників жестів, серед яких `TapGestureHandler` використовується для одиночних або множинних кліків (наприклад, 
для активації кнопок чи отримання очок), `LongPressGestureHandler` — для тривалого утримання елементів з метою виклику контекстних меню або
бонусів, `PanGestureHandler` — для вільного перетягування об'єктів по екрану, `FlingGestureHandler` — для швидких свайпів у визначених 
напрямках (горизонтально чи вертикально), а `pinchGestureHandler` та `RotationGestureHandler` — для масштабування та обертання двома 
пальцями. Вони забезпечують нативну продуктивність виконання жестів без затримок JavaScript-потоку.
+
+**2. У чому відмінність між обробкою переміщення об'єкта за допомогою PanGestureHandler та швидкого зсуву через FlingGestureHandler?**
+
+`PanGestureHandler` призначений для безперервного відстеження рухів пальця (перетягування), де об'єкт плавно слідує за координатами пальця
в реальному часі під час жесту. Натомість `FlingGestureHandler` реагує на швидкий спрямований рух (свайп), який фіксується як дискретна 
подія у момент завершення швидкого поштовху, після чого може спрацьовувати анімація або нарахування бонусів залежно від напрямку свайпу.
+
+**3. Навіщо у корені застосунку необхідно обгортати компоненти в GestureHandlerRootView?**
+
+Компонент `GestureHandlerRootView` створює нативний кореневий контейнер обробки жестів для платформ Android та iOS. Оскільки 
`react-native-gesture-handler` залежить від нативної ієрархії представлень (native views), обгортання кореневого компонента (у 
`_layout.jsx`) гарантує, що всі дочірні екрани та компоненти матимуть доступ до контексту жестів та коректно розпізнаватимуть дотики на 
рівні нативного потоку UI.
+
+**4. Яким чином можна реалізувати одночасне або послідовне спрацьовування кількох жестів на одному елементі?**
+
+Для послідовного або одночасного виконання кількох жестів використовуються методи композиції жестів `simultaneousWithExternalGesture`, 
`sequential` або метод `simultaneous` із залученням Gesture API. Це дозволяє, наприклад, комбінувати перетягування `Pan` та масштабування 
`Pinch` на одному об'єкті так, щоб вони не конфліктували між собою, а виконувалися або одночасно, або за чітко визначеною пріоритетністю.
